# 测试与迁移发现

标准检查入口为 `npm test`，其中 `npm run test:node` 使用 `scripts/run-node-tests.mjs` 递归发现 `test/` 下的 `*.test.mjs`。支持字母、数字、下划线、连字符、点和嵌套目录。helper 模块由测试导入，不再作为空测试单独发现。直接运行 `node --test` 仍使用 Node 默认规则，不具备本项目的副本排除行为；针对性检查可显式传入测试文件。

空格加数字的副本名称是保留排除模式，例如 `example.test 2.mjs`、`example 2.test.mjs` 或 `folder 2/`；不删除这些文件。其他 test-like 文件（例如不支持的 `.test.js`、`test.mjs`、带空格的新测试名）明确报错，避免未来测试被静默漏掉。`node_modules`、`.git` 不进入扫描，测试树内符号链接明确拒绝。没有测试时检查失败。

Cloud 测试 harness 的迁移发现只接受四位数字、下划线、名称和 `.sql` 的形式，例如 `0012_add-index.sql`；非副本 SQL 名称不符合约定时明确报错。当前源码中的两组同编号、不同名称迁移仍按完整文件名排序全部执行，不按编号或内容去重。数字副本不会再次执行相同 ALTER；合法迁移中真正的 SQL 错误仍导致测试失败。

此修改覆盖本地测试 harness，不改 Wrangler 的生产迁移发现或远端数据库，也没有执行 cloud 部署。不要据此在含未知副本的目录直接运行生产迁移命令。

## 现有副本调查与验收

2026-09-15 本机调查发现 69 个未跟踪数字副本，其中 62 个与对应原文件 hash 一致，7 个不同。文件时间和名称不足以证明创建者或归因为同步软件，来源保持未知。全部原件保留，已在仅本机的证据目录保存清单、备份，并在隔离目录逐一恢复核对 hash；原件复核未变。没有清理或覆盖未知内容。

含副本的原 checkout 文件发现结果与 Git 跟踪清单完全一致（44 个测试文件、13 个 SQL）；这是文件发现验证，没有在旧 checkout 上运行旧版本全套测试。干净工作树另跑标准检查。

回归覆盖：Node 默认发现会执行人为放入的坏副本而失败，标准 runner 通过；真实规范测试失败仍退出 1；嵌套测试确实执行；Miniflare 使用复制的完整迁移目录，额外 ALTER 副本不执行，尝试再次执行该 SQL 会报重复列；合法 SQL 语法错误仍被报告。针对性命令：`node --test test/source-discovery.test.mjs`。

若以后处理副本，先核实对应原件和来源、保留备份，再按单独清理范围操作；测试通过不构成删除授权。备份清单及本机恢复证据由个人开发台账引用，不提交仓库。
