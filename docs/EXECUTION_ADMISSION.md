# 执行准入记账

`ExecutionAdmissionStore` 扩展项目策略库，在同一 SQLite 事务中读取最新策略、检查范围、预留次数与并发。此模块属于 #24 的协调器基础，不调用模型、不创建会话，所有决策均保留 `authorizesDispatch:false`。实际派发还必须接入最新任务快照、可信执行意图、有效工具权限和绑定回执。

## 状态与计数

- `reserve` 检查指定策略版本和请求范围，预留 30 秒。项目并发包括 reserved、started、unknown；任务 ID 的在途唯一性跨项目生效。
- `start` 再次检查策略、任务语义摘要及完整请求，并重新检查预算。暂停在相同数据库提交后，旧预留无法开始。start 已提交的记录属于在途工作，之后暂停不能被解释为已停止该工作。
- 未开始的预留过期后变为 cancelled，释放次数和并发；started 不自动超时释放。执行结果不明确时保留占用，禁止自动重试。
- `finish` 接受可信适配器提供的终态回执，释放并发但保留当日次数。同任务、同语义版本再次申请返回原回执；更改策略版本不允许重跑。当前没有解锁已完成语义或 unknown 的接口，后续人工对账需要独立设计。

日次数按 UTC 日期计算，不跟随本机时区；跨午夜开始会在新日期重新核验额度。完成记录一直保留用于去重，当前没有自动历史清理。这里的预算是派发次数和并发，不能作为 token 费用上限。`maxCallsPerRun` 仅核验请求范围，实际调用次数还需执行器强制执行。

语义摘要来自上游候选模块，不能让模型直接提供新的摘要以规避去重。系统状态写回或自动评论导致的摘要变化也不能自行授予新执行意图；这是后续协调器接入验收的一部分。SQLite 只能协调遵守协议的进程，无法隔离能任意改写同用户文件的全权限执行者。

## 升级、恢复与停止

首次使用在现有策略 schema 1 上增量加入准入表，升级至 schema 2，保留所有策略历史。当前更新的策略 CLI 可读取两版；旧 schema-1-only 二进制会拒绝升级后的数据库。此库与候选扫描状态库具有不同 application ID，不能互相替代。

升级前停止持有该控制库的自建进程，复制完整数据库备份；当前 rollback journal 模式下禁止运行时裸拷贝。恢复先在隔离路径打开并检查策略、在途和已完成回执。不得恢复旧快照后直接重新派发：快照之后发生的外部执行可能未在备份中，必须先对账。重开数据库保留 started/unknown，不能把进程消失当作任务未执行。

本阶段未注册服务、启动项或 CLI 派发入口，不修改正式 App、旧 scheduled 或原生任务数据库。操作者原有 pause 只暂停未来策略准入，停止已运行会话仍为独立操作。

## 验证范围

回归覆盖并发名额、暂停版本、日额度、午夜转换、语义变化、完成去重、进程竞争、SIGKILL 后保留占用、另一进程暂停、旧策略库升级及隔离备份回执。隔离测试不代表真实模型权限、运行时调用预算或桌面会话停止已通过。
